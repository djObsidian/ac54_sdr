## Методика

Приёмник: ASUS USB-AC54 (`0b05:1841`), RTL8822BU, тракт A, BW20.
Источник: LibreSDR Rev.5 / AD9361, обнаруженный как PlutoSDR,
`usb:4.1.5`, серийный номер `QBRSU2UZB5GB4OX6`, TX1.
Связь через антенны, без калибровки уровня или чувствительности.

Перебираются **все 160 аппаратных центров**, допускаемые отображением частоты
в `spyserver.c`: каналы 1–14 и каждый целый номер 32–177. Для каждого центра
`init.exe` заново выполняет питание, чтение efuse, загрузку BB/RF-таблиц и
настройку BW20. Это исключает зависимость результата от настроек предыдущего
канала в промежутках между обычными группами Wi-Fi-каналов.
Утилиты `init`, `reg`, `la`, `cpustream` и `spyserver` пересобраны из исходников.

В каждой точке записываются три состояния: DDS выключен, тон на **центр +1 МГц**,
тон на **центр +2 МГц**. На состояние приходится три LA-снимка по 16 384
комплексных отсчёта, 40 MSPS. Передатчик: DDS 1 МГц, scale 0,25;
смена частоты выполняется через TX LO. Основной проход — TX attenuation 20 дБ.
CCK при съёмке отключён. Считывается номер канала из RF18 обоих трактов,
но сами I/Q проверяются только для тракта A.

Для анализа берётся медиана трёх спектров с окном Hann. Мощность тона —
сумма девяти FFT-бинов; локальный фон оценивается на расстояниях 40–200 кГц
от пика. Проверка требует одновременно:

- совпадения номера канала в RF18 A/B с запрошенным;
- локального отношения сигнал/фон не менее **15 дБ** для обоих тонов;
- превышения уровня при выключенном DDS не менее **6 дБ** в тех же бинах;
- ошибки частоты относительно +1/+2 МГц менее **150 кГц**;
- смещения пика на 1 МГц с погрешностью не более двух FFT-бинов (**4,883 кГц**);
- доли отсчётов у предела шкалы менее **0,1%**.

На некоторых частотах рядом с +1-МГц тоном виден более сильный побочный пик.
Поэтому итоговый анализ сначала находит +2-МГц тон, а затем ищет +1-МГц
составляющую в пределах двух FFT-бинов от положения, предсказанного общей
ошибкой генераторов. Пороги сигнал/фон и включено/выключено сохраняются.
Причина побочных составляющих этим опытом не установлена.
`results.*` сохраняют исходный выбор самого сильного пика, `analyzed.*` —
итоговый анализ с сопоставлением двух тонов.

## Ограничения

Это проверка настройки и обнаружения известного тона вблизи центра на данном
экземпляре адаптера. Она не определяет чувствительность, калиброванную АЧХ,
полосу по −3 дБ, чистоту спектра или устойчивость непрерывного потока на
каждом канале. Обычные группы RF/BB-таблиц — 36–64, 100–144 и 149–177;
испытание промежуточных номеров не превращает их в штатные Wi-Fi-каналы.
Покрытие за пределами проверенных центров не установлено.

`cpustream` по-прежнему настраивает канал 11 / **2462 МГц / BW20**.
Частота опроса в его аргументах не меняет RF-центр. SpyServer использует
прежний путь захвата DDMA, а не новый CPU-стример 20 MSPS.

## Повторение

Нужны MSVC/Windows SDK, WinUSB, USB 3, Python с NumPy и libiio CLI в PATH.
Оба устройства доступны одному процессу проверки; другие программы работы
с ними должны быть закрыты. Указывайте новый каталог вывода.

```bat
cd tools
mk.bat init
mk.bat reg
mk.bat la
cd ..
python tools/validate_tuning.py --uri usb:4.1.5 --out artifacts/response-tuning-new
python tools/analyze_tuning.py artifacts/response-tuning-new
```

Проверка верхнего края при большем уровне передатчика и цифровой подстройки:

```bat
python tools/validate_tuning.py --channels 175,176,177 --gain=-10 --out artifacts/response-tuning-edge-new
python tools/analyze_tuning.py artifacts/response-tuning-edge-new
cd tools
mk.bat spyserver
cd ..
python tools/validate_spy_tuning.py --out artifacts/response-tuning-spy-new
```

Для короткой проверки можно передать, например, `--channels 1,14,32,36,100,149,177`.
Код возврата захвата отражает первоначальный независимый выбор пиков;
итоговые результаты сопоставления находятся в `analyzed.csv` и `summary.json`.
При завершении DDS отключается, настройки Pluto восстанавливаются,
адаптер возвращается на канал 11. Сырые `.bin` остаются локально и исключены
из Git; таблицы, метаданные и журналы инициализации включены в репозиторий.
